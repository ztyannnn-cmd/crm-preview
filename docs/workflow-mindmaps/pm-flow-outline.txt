PM 业务流程 · AJ · seven
	01 项目＋地区确定负责 PM
		阶段详情
			进入条件
				提报已有项目与目标地区，需要确定负责 PM
			操作人员
				超管：配置路由、调整规则、交接存量
				PM：处理分配给自己的提报与视频
			页面操作
				超管配置每个项目的地区路由
			状态变化
				确定负责 PM；不新增审批状态
			条件分支
				示例：Tripo＋美国 → AJ
					Tia、Jennie 提报均进入 AJ 审核
					其他项目与地区可分配不同 PM
				地区路由未命中 → 使用项目默认 PM
			业务规则
				负责首次提报及后续全流程
					报价、脚本、视频、发布验收
					人员变更：超管调整规则／交接存量
				仅处理分配给自己的提报与视频
			下一阶段
				文字引用：02 首次提报审核
		02 首次提报审核
			阶段详情
				进入条件
					提报已分配负责 PM，处于待 PM 审核
				操作人员
					PM：审核
					运营：查看反馈、调整并重新提报
				页面操作
					查看待 PM 审核记录
					核对达人与合作方案
						地区、平台账号、粉丝、均播
						视频类型、数量、权益、合作总价
				状态变化
					待 PM 审核 → 待 PM 反馈／不予提报
				条件分支
					审核通过 → 待 PM 反馈
						可提交首轮对客报价
					不予提报 → 必须填写原因
						运营查看反馈，可调整后重新提报
						确认不提报
						重新提报
							返回提报页面
							重新提交 → 返回 02 首次提报审核
				业务规则
					不予提报必须填写原因
				下一阶段
					文字引用：03 报价与客户沟通
			03 报价与客户沟通
				阶段详情
					进入条件
						PM 首次提报审核通过
					操作人员
						PM：对接客户、登记报价及客户结果
						运营：对接达人、提交运营回价
					页面操作
						提交整包对客报价与备注
							使用方案币种，记录本轮金额
							状态：议价待客户确认
						运营报价后，客户提出新方案 → PM 填写到系统 → 运营向达人确认
							合作条件变更 → pm可直接编辑，更新方案再返回运营确认
							达人接受客户新方案 → PM 先登记该版方案客户同意 → 运营创建订单
					状态变化
						状态：待客户确认
							网站当前名称：议价待客户确认
						客户还价 → 待运营议价；运营回价 → 待 PM 反馈
					条件分支
						客户还价 → 登记 → 交运营议价
							状态：待运营议价
							收到运营回价 → 待 PM 反馈
						运营回价后决定下一步
							继续下一轮对客报价，最多 3 轮
							合作条件变更 → 更新方案再确认
							第 3 轮后登记最终结果，不报第 4 轮
						客户接受 → 登记价格与备注
							不必报满 3 轮即可确认合作
							状态：待达人确认 → 交运营
						客户拒绝 → 填原因 → 客户不合作
						客户不合作
							pm填写原因
						第三轮仍未达成一致 → 继续等待最终结果，不新增第四轮对客报价
					业务规则
						最多 3 轮对客报价；不要求报满 3 轮
							确认成交后，使用最新达人回价更新整包合作价，再计算 Margin 和单条视频分摊
						客户新方案由 PM 录入，再由运营向达人确认
					下一阶段
						文字引用：04 合作确认与交付准备
				04 合作确认与交付准备
					阶段详情
						进入条件
							PM 已登记客户接受，进入待达人确认
						操作人员
							运营：确认达人、创建订单、提交注册邮箱
							PM：补登客户确认、填写邀请信息
						页面操作
							确认成交后，用最新达人回价更新整包合作价，再创建订单
							运营确认达人并创建订单
								提报完成；视频以独立 ID 继续推进
								每条视频有合作价、对客价、Margin
							运营提交平台注册邮箱后
								PM 填写邀请码＋邀请链接
								同订单共用；不阻塞脚本制作
						状态变化
							创建订单 → 提报完成；视频以独立 ID 继续推进
						条件分支
							客户接受记录对应当前方案版本
								版本变化后重新登记客户确认
								历史缺失的确认由负责 PM 补登
						业务规则
							每条视频有合作价、对客价、Margin；邀请信息同订单共用，不阻塞脚本制作
						下一阶段
							文字引用：05 脚本和视频审核
					05 脚本和视频审核
						阶段详情
							进入条件
								当前最新脚本／视频已提交 PM
							操作人员
								运营：提交稿件、修改并重提
								PM：初审、送客户、登记客户反馈
							页面操作
								脚本初审：核对当前最新稿
									通过 → 待送客户；退回需修改意见
									标记已送客户 → 等待客户反馈
								登记脚本客户反馈
									通过 → 进入视频制作
									修改 → 退回运营 → 重提下一稿
								视频初审：核对当前最新稿
									通过 → 送客户；退回需修改意见
								登记视频客户反馈
									通过 → 待发布
									修改 → 退回运营 → 重提下一稿
							状态变化
								脚本：PM 通过 → 待送客户 → 等待客户反馈 → 客户通过 → 视频制作
								视频：PM 通过 → 送客户 → 客户通过 → 待发布
							条件分支
								脚本被 PM／客户退回 → 运营修改并重提 → 返回本阶段脚本初审
								视频被 PM／客户退回 → 运营修改并重提 → 返回本阶段视频初审
							业务规则
								审核意见绑定版本、来源、处理人和时间
								初审核对当前最新稿；退回需要修改意见
							下一阶段
								文字引用：06 发布验收与工作边界
						06 发布验收与工作边界
							阶段详情
								进入条件
									运营已提交发布链接 → PM 验收
								操作人员
									PM：验收并登记结果
									运营：补充发布资料
									超管：地区 PM 变更与存量交接
								页面操作
									运营提交发布链接后 → PM 验收
										核对各平台链接与已确认方案
										通过 → 本条视频已完成
										资料不足 → 写原因 → 退回运营补充
								状态变化
									单条视频验收完成 → 本条视频已完成
									同一订单全部视频完成 → 订单显示已完成
								条件分支
									资料不足 → 填写原因 → 退回运营补充 → 返回本阶段验收
									还有视频未完成 → 订单不显示已完成
								业务规则
									待我处理／等待他人 → 按项目管理
									对接客户；运营对接达人
									地区 PM 变更与存量交接由超管操作
									历史可折叠；抽屉不跨页面跳转
									口径：CRM 原型 · 2026-10-13
								下一阶段
									本条视频完成；同订单全部视频完成后订单显示已完成，不增加付款审批
