# 提报跟进前端交接

2026-10-20｜本次按用户批准的方案简化提报跟进页：收拢筛选和发起入口，固定表格及双方报价列，移除多视图设置。沿用原生 ES Modules / HTML / CSS 和现有 `model.mjs`，仅修改前端，未接入真实 API，未修改后端。

## 本轮页面与数据边界

- 页面使用紧凑筛选区；“发起提报”并入筛选首行。主要处理范围为“待我处理 / 等待他人 / 全部提报”三个标签，“今日待跟进 / 已逾期”作为次级入口；五个选项共同控制同一个互斥的处理范围，每次只选一个，不作为叠加筛选。
- 合作阶段单独展示，零计数阶段弱化视觉；搜索、项目、阶段及高级筛选项均生成已选条件标签，可逐项移除或一次清空。排序放入“更多筛选”，默认“待我处理优先（pending）”。
- 结果栏仅显示“共 N 条结果”。提报跟进固定使用表格，双方报价列始终显示；移除该页的列表/看板/日历切换、视图设置、保存视图和管理视图入口。
- 下一步入口打开已有提报详情，不在列表直接提交审核、报价或建单。列表保留当前处理人和明确的报价来源。无提报时使用紧凑空状态，标题“还没有提报”，提供“选择达人提报”次级链接。
- 提报详情抽屉、达人管理、项目管理、视频交付不属于本轮页面重做范围。
- 现有数据入口：[http://127.0.0.1:8897](http://127.0.0.1:8897)。沿用业务键 `solbridge-video-v06-preview-only`；本次列表简化不清空、替换或导入浏览器数据。此前另获授权的手动清空及空库初始化见文末历史记录，不能解释为本次再次执行清空。
- 独立评审入口：[http://127.0.0.1:8897/?demo=followup](http://127.0.0.1:8897/?demo=followup)。业务数据及视图偏好均使用独立内存，不读取或写入浏览器 LocalStorage / SessionStorage；刷新重新生成样例，页面提供“返回现有数据”链接。
- 恢复旧 session 中的提报跟进偏好时，强制 `view='list'`、`settingsOpen=false`、`activeView=''`，避免旧看板/日历或设置状态重新出现。业务数据中的 `savedViews` 保留，不删除、不迁移；其他页面的视图能力不受本次跟进页收敛影响。
- 模拟账号切换仅供原型评审，不代表可信登录或服务端鉴权。现有数据没有提报时显示空状态，不以此推断功能缺失。

## 后端所需数据

以下为列表对接所需信息；字段名是交接建议，须由后端 DTO/schema 定稿。现有本地模型字段不能直接视为共享接口。金额在规划契约中使用十进制字符串，不能以 JSON number 传输或静默取整。

| 信息 | 所需字段/含义 |
|---|---|
| 标识与范围 | `id`、`proposalCode`、`creatorId`、`campaignId`；当前工作区及可见范围由服务端会话决定，不能由浏览器角色参数授权 |
| 达人与项目 | 达人展示名/编号、账号平台/handle/主页、国家；项目名称及可参与项目选项。只返回列表/筛选必要资料，不夹带无权查看的合作或报价 |
| 内容摘要 | 当前有效方案 `versionId`、展示版本号、合作项的平台/类型/原创数量/分发平台；项目/视频列据此生成摘要 |
| 归属与自提 | 业务负责人 ID/显示名、实际审核 PM ID/显示名、明确的自提归属。PM 自提负责人可能是 PM，不应一律解释为运营 |
| 阶段与进度 | 稳定的阶段/状态代码、展示文案、是否已成单/已结束、关联 `orderId`；保留历史兼容状态映射，不由前端猜测成交确认 |
| 当前处理人 | 当前承接人 ID/显示名、处理事项和等待说明；可包含“等待客户反馈，由 PM 登记”。应与状态和动作能力同源，不只根据角色或负责人推断 |
| 操作能力 | 逐记录 `capabilities`、允许的下一步动作、必要禁用原因及详情查看能力。列表显示入口不替代服务端逐次校验 |
| 报价摘要 | 币种、当前有效达人价、对应方案/轮次；对客报价草稿、当前方案正式报价、客户明确接受价分别提供来源/版本/时间。每次正式对客报价必须关联明确的 `proposalVersionId` / `versionId`，并提供可判定报价与方案先后关系的服务端时间或序号；成单后返回锁定成交快照 |
| 更新时间 | `updatedAt`、必要的最新变更说明；提交时间可用于没有更新证据的历史记录 |
| 当前进度停留 | 建议 `statusEnteredAt`、服务端参考时间/时区、计时是否适用及缺失原因；必要时提供进度事件证据。不得用普通备注更新时间替代 |
| 跟进与日期 | 本人未完成提醒的归属、状态、到期时间。预计发布日期仍可保留在业务详情/其他既有模块，但本页已移除日历入口，不把它与提醒到期日混用 |
| 草稿摘要 | 仅本人可见的提报草稿 ID、达人/项目、保存时间、版本及可恢复入口；不计为正式提报或审核待办 |
| 分页与统计 | 当前权限/筛选范围的总数、游标，以及处理范围/阶段统计；不能用当前一页条数冒充总数 |
| 一致性 | 聚合版本/ETag、当前方案 ID、请求 ID；写操作需幂等键及明确成功/失败/结果待核实反馈 |

| `GET /api/v1/bootstrap` | 小规模首次加载所需的可见达人、项目、提报、本人草稿、显示姓名及 capabilities/versions；不可下发全库后再由前端过滤 |

## 权限、统计与时间口径

业务依据为 [已确认规格](../specs/001-proposal-to-order/spec.md) 的权限矩阵和状态表：运营负责本人达人侧报价及建单；实际审核 PM 处理审核/客户侧；直属 PM 只读直属业务及双方金额；管理员管理并查看测试业务，不代业务；PM 自提本人承担两侧职责且免提报审核。列表、搜索、统计和详情必须遵守同一记录范围。

固定展示双方报价不扩大数据范围：前端继续沿用 `visibleCoops`，各角色仅对其可见提报展示双方金额；该查看权限不授予另一侧报价的修改权。后端须先过滤记录范围，再返回对应金额及 capabilities，不能全量下发后依靠隐藏列保护数据。

当前原型继续调用 `model.mjs` 计算范围和统计。后端对接时应保留清楚的过滤口径，并让列表和计数来自同一快照：

| 区域 | 当前页面口径 / 对接要求 |
|---|---|
| 待我处理 | 当前用户有下一步动作，或本人有未完成提醒；不能仅凭“负责运营/审核 PM”字段判断 |
| 等待他人 | 当前用户无可执行动作、尚未结束的可见记录，排除已成单；保留待运营处理的拒审记录。它与提醒队列的数据集合可能交叉，但界面一次只选择一个处理范围，不将各范围计数相加为总数 |
| 今日待跟进 | 本人未完成提醒到期日为今天；不等于全部待办。现有样例未预置提醒，因此可为空；共享服务须明确工作区时区，不能受不同浏览器时区影响 |
| 已逾期 | 当前原型中，可计时的未成单提报在当前具体进度停留 **大于 12 小时**；不是预计发布日期逾期，也不等于提醒超时。这是沿用现状口径，不新增承诺 SLA |
| 处理范围标签数 | 保留搜索、项目及具体筛选，取消阶段限制后分别计算各队列数量 |
| 进行中阶段标签数 | 在当前处理范围和其余筛选下，忽略当前阶段再分组；零计数只弱化视觉，不另定义业务状态 |
| 已完成/已取消标签数 | 从“全部提报”计算对应终态范围，忽略具体进度筛选；点击会切换到全部提报并清除具体进度/指标限制，避免终态被待办范围隐藏 |
| 结果条数 | 结果栏仅显示“共 N 条结果”，N 为当前全部筛选的结果；接分页后必须用服务端总数，不取当前页长度 |

停留时间从进入**当前具体进度**的有效证据起算，显示一位小数。备注、普通资料更新和仅保存草稿不能重置它；没有可靠时间、已成单或不适用的历史/结束状态显示 `—`。最近更新时间单独展示，可以随备注或其他编辑变化。后端最好直接提供可信 `statusEnteredAt`，避免前端从不完整历史重建。

## 报价语义与异常恢复

- **提报草稿**是尚未正式提交的资料；**对客报价草稿**是提报内未正式发出的价格，两者不能混为同一状态。样例 Olive 属于后者。
- 保存报价草稿不占正式报价轮次，也不等于已经发给客户；正式报价仍不等于客户接受。客户还价与客户接受须分别记录。
- 两侧金额及当前方案关联分别展示；失效旧方案的接受或报价不能作为当前有效值。成单后展示成交金额快照，普通改价锁定；负 Margin 提示但不阻止合法建单。
- 当前旧模型可能保留正式报价历史而缺少报价的方案归属。列表优先核对报价 `versionId` 是否等于当前方案 ID；对于 **V2 及以后、缺少版本归属**的旧报价，只有 `quote.at` 和 `version.at` 都有效且 **`quote.at > version.at`** 才按当前报价展示。同一毫秒不能证明先后，按待确认处理，不猜测属于当前方案；无有效草稿/接受/成交依据时显示“待确认 / 暂无有效报价”。这是列表的保守兼容展示，历史仍保留在详情，不改写或删除旧报价。
- 写操作带聚合 ETag/`If-Match`、`Idempotency-Key`，方案 `versionId` 与聚合版本不是同一字段；业务 payload 不发送任意 actor/role/owner 授权信息。
- 401 会话失效、403 权限变化：保留未提交输入，重新获取身份/权限，不自动重放；无查看权用 404，避免泄漏记录存在。
- 409 版本冲突：保留输入，展示可见最新值供核对；在途提报/归属不明给安全提示。同幂等键不同内容的冲突不能靠自动换键绕过。
- 422 校验失败定位字段并保留输入，金额不能静默取整；428 缺版本需重新读取并核对。
- 503/网络中断且结果不明：不显示假成功，保留原幂等键与内容，查询原 operation；同一提报不得生成第二单。具体错误结构沿用契约。

## 已知边界

- 本轮列表中的管理员下一步入口仅显示“查看详情”，但旧详情/模型仍可能提供管理员业务按钮；本轮没有重做详情或完成管理员禁代业务。不能将列表按钮限制当作鉴权完成证明。
- 当前模型仍沿用既有状态名称与兼容映射。例如“已完成”阶段可能包含“价格已确认（待创建订单）”；首次正式报价后也可能显示旧“待客户报价”文案。后端接入前须依据已确认规格统一稳定状态、显示文案及终态口径，不能仅凭标签推断已经成单。
- 正式报价的方案归属缺失仍是数据契约缺口；前端时间比较只用于兼容旧记录，不能替代后端可靠的版本关联和事件顺序。正式接口须写入报价的方案 ID 及服务端时间/序号，不能要求列表长期从历史数组或同毫秒时间推测。
- 共享登录、服务器权限、跨设备持久保存、并发版本冲突、真实网络失败恢复均未由这次前端页面实现或验收。
- 提报详情保留既有业务呈现；跟进页已移除看板、日历及视图设置入口。独立演示操作成功仅证明模拟路径可供评审，不代表真实共享链路已通过。

## 同事评审步骤

1. 打开独立演示入口，确认“独立演示”提示；切换 AJ / Tia，对比三个主要范围和“今日待跟进 / 已逾期”次级入口，确认五个选项同属一个互斥范围。使用“运营 · Jennie”检查紧凑空状态“还没有提报”及次级“选择达人提报”链接。
2. 检查“发起提报”位于筛选首行；切换阶段、项目、搜索和高级筛选，确认已选标签涵盖这些条件且可逐项移除、清空。核对零计数阶段弱化、结果栏只显示“共 N 条结果”；在更多筛选中切换排序，默认应为待我处理优先。点击已完成/已取消，核对范围自动切换是否清楚。
3. 确认固定表格且双方报价始终显示，没有列表/看板/日历切换、视图设置、保存或管理视图入口。比较 Olive 的未提交草稿、Pixel 的正式报价、Lena 的客户已接受以及 Atlas 的成交金额；检查币种、来源说明和当前处理人。
4. 对比 Northlight/Pixel 的停留时间与最近更新时间；检查已成单记录显示 `—`。今日待跟进为空时应说明提醒口径。
5. 点击列表行或“下一步”打开已有抽屉，再返回列表；在独立演示中可尝试现有动作。确认返回时筛选、滚动位置和焦点仍便于继续操作。
6. 检查窄屏：页面主体不被固定表格撑宽，数据容器可横向滚动。通过隔离测试验证旧跟进页 session 的看板/日历/打开设置状态恢复后被归一到列表、关闭设置和无 activeView；业务 `savedViews` 原样保留。
7. 刷新独立演示，确认恢复原 8 条样例；点击“返回现有数据”，确认保留当前普通入口数据状态。不以清空存储的方式重新生成样例。
