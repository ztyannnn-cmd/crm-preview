## 1. 用户与目标

**已确认**：运营与 PM 需要按权限协作处理同一份隔离测试记录，刷新及重新登录后结果仍保留，身份和权限可信校验。首轮主线是 **提报 → 审核报价 → 生成订单**。
PM 可提报自己的达人，免提报审核、填双方报价；先正式对客报价，客户接受、达人确认后本人建单，并对本人自提记录负责到最终视频验收，不扩大其对其他运营记录的操作权。

## 4. 范围与限制

区分长期责任与首轮开发范围：首轮主线到成单为止，不重做通用视频模块，不把视频全部验收作为提报成单的完成门槛；已获授权的 PM 自提及视频权限增量保留。
不新增合同付款、自动邮件、成单后改价/撤回或交接工作台。本轮只改规格和说明文档，不继续开发、安装、迁移或部署，保留所有既有修改与数据。
技术栈是代码事实，不等于已批准选型；历史 PostgreSQL 设计与当前 MySQL 实现分别保留证据。指南中的字段/业务规则无可核对确认原文时仍为建议。技术选择、登录办法、存储/接口和后端 Git 管理留到第 4 步。

## 5. 已确认事项与阶段交接

- Q1 已解决：运营负责本人提报及达人价/确认/建单；审核 PM 负责分配审核及客户价/反馈；直属 PM 只读直属业务与双方金额，其他同事不看他人明细；用户指定测试管理员管理身份/角色/项目分配并可查全部测试业务，不代业务。
- Q2 已解决：采用规格 FR-003/004/006 的字段、本人草稿、单份在途与负责人再次合作规则；代码拦截差异留后续处理。
- Q3 已解决：审核未通过原因必填、原记录补说明复审或结束、复审不限次不自行换人；运营实质方案变更回审（保持条数补正例外），PM自提免审；报价不限轮、正式反馈/回价后移交；最终两侧成交金额同币种、正总额、最多两位小数，默认均分余分按序，允许分侧手动拆分且合计一致，负Margin提示但不拦截；一提报一单，成单保留并锁定普通改价，不新增撤回/纠错。

PM 自提免审核、成交前置与负责到验收不再重复询问。上述关键规则均有用户答复，21项需求/30个验收场景已对齐，规格质量检查16/16，第3步完成，可进入第4步。共享业务尚未实现本身是后续方案要解决的差距，不要求先开发完才进入方案。
